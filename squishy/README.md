# 말랑말랑 찹쌀이

손가락으로 꾹 누르고, 쭉 당기고, 접시째 흔들어 보는 3D 말랑이예요. 주인공은 귀가 쫑긋하고 머리에 새싹이 난 동글동글 찹쌀떡 **찹쌀이**예요.

찹쌀이의 몸은 애니메이션이 아니라 **실제 소프트바디 물리 계산**으로 움직여요. 몸 안을 사면체 수천 개로 채운 볼륨 메시를 XPBD로 풀고, 그 결과를 GPU가 고해상도 피부에 입혀요. 그래서 누른 자리만 들어가는 게 아니라 주변이 함께 밀려나고, 세게 누르면 몸 전체가 찌부러지고, 놓으면 탄성과 점탄성에 따라 출렁이거나 천천히 부풀어 올라요.

## 만지는 법

| 동작 | 반응 |
| --- | --- |
| 꾹 누르기 | 손끝 모양대로 쏙 들어가고 주변 살이 밀려나요. 오래 누를수록 더 깊이 들어가요(점탄성 크리프) |
| 세게 누르기 | 몸 전체가 찌부러지고 옆이 불룩해져요. 마우스는 Shift, 누른 채 휠로 힘 조절, 펜·일부 터치스크린은 실제 압력을 써요 |
| 누른 채로 끌기 | 피부가 손가락에 붙어 끌려가요. 마찰 한계를 넘으면 미끄러지며 따라와요 |
| 귀 잡아당기기 | 얇은 귀는 꼬집듯 잡혀서 쭉 늘어나고, 몸 전체가 따라 기울어요. 너무 세게 당기면 "뾱!" 하고 빠져요 |
| 두 손가락 | 서로 다른 곳을 동시에 누르거나, 한 손가락으로 누른 채 다른 손가락으로 끌 수 있어요 |
| 접시 끌기 | 접시를 잡고 흔들면 몸이 관성으로 뒤늦게 따라오며 출렁여요. 놓으면 진동이 감쇠하며 멈춰요 |
| 톡톡 두 번 | 폴짝 점프해요. 착지할 때 찌부러지는 것도 계산 결과예요 |
| 빈 곳 드래그 / 두 손가락 벌리기 | 빙글 돌려보고 확대·축소해요. 빈 곳을 두 번 톡톡 치면 처음 시점으로 |

키보드: 화면 선택 후 스페이스(누르기, Shift로 세게), 화살표(돌리기), J(점프), S(흔들기).

손가락 주변의 링은 손끝 접촉 크기와 지금 누르는 힘(N)을, 끌 때는 늘어난 길이(mm)를 보여줘요.

## 말랑함 세부 설정

오른쪽 위 조절 버튼을 누르면 여덟 가지 값을 실시간으로 바꿀 수 있어요. 각 슬라이더는 시뮬레이션의 실제 물리량 하나에 연결돼 있고, 그 값을 단위와 함께 보여줘요(1단위 = 4 cm, 밀도 650 kg/m³).

| 설정 | 물리량 | 하는 일 |
| --- | --- | --- |
| 말랑함 | 영률 E (2.5–40 kPa) | 사면체 스프링망의 강성 k = 6·E·V/L². 낮을수록 같은 힘에 더 깊이 들어가요 |
| 탄성 계수 | 형상 기억 스프링 k = mω² | 형상 정합(shape matching)의 복원 강성. 몸 전체를 원래 모양으로 끌어당겨요 |
| 점성 계수 | 맥스웰 가지 점성 η = g·E·τ | 표준 선형 고체(Zener)의 점성 가지 세기 g. 눌린 모양을 오래 기억해요 |
| 감쇠 계수 | 켈빈–포크트 감쇠 β (ms) | 강성 비례 감쇠. 놓은 뒤 출렁임이 잦아드는 빠르기 |
| 복원 속도 | 이완 시간 τ (s) | 점성 가지의 이완 시간. 짧을수록 빨리 부풀어 올라요 |
| 변형 반경 | 손끝 접촉 반경 a (mm) | 힘이 퍼지는 넓이와 손끝 자국의 크기 |
| 압축 강도 | 푸아송 비 ν, 체적 탄성률 K | 낮으면 눌린 만큼 부피가 줄고, 높으면 부피를 지키며 옆으로 불룩해져요 |
| 표면 반응 강도 | 피막 장력 Y (N/m) | 피부 막 스프링과 라플라시안 굽힘 강성. 높을수록 눌림이 넓고 매끈하게 퍼지고 주름이 굵어져요 |

**질감** 버튼(말랑·탱글·쫀득)은 이 여덟 값의 묶음이에요. 말랑은 메모리폼처럼 천천히 부풀고, 탱글은 통통 튀며 출렁이고, 쫀득은 길게 늘어나요.

같은 패널에서 시뮬레이션 품질(자동·낮음·보통·높음)을 고를 수 있고, 입자 수·사면체 수·서브스텝·물리 계산 시간이 표시돼요.

## 물리 구조

```
입력(포인터) ──► 메인 스레드 ──메시지──► 물리 워커 (60 Hz 고정, 자체 시계)
                   │  정밀 피킹                │  XPBD 서브스텝 × N
                   │  상태 보간 ◄──상태 버퍼──┘  (주고받는 버퍼 재사용)
                   ▼
              GPU: 입자 텍스처 → 정점 셰이더 스키닝 → 조명·그림자·주름
```

### 쓰인 기법과 조합 방식

모든 기법을 다 쌓지 않고, 안정성과 성능을 기준으로 역할을 나눴어요.

- **XPBD (주 솔버)**: 프레임마다 서브스텝 12–18개, 서브스텝마다 가우스–자이델 한 번(small steps). 모든 구속 조건이 정지 상태에서 0이 되도록 골라서 무조건 안정적이에요. 처음에는 Neo-Hookean 구속을 검토했지만 편차 구속이 정지 상태에서 0이 아니라 전단 모드가 터지려면 서브스텝이 4배 필요해서, 아래의 스프링망 + 부피 조합으로 바꿨어요.
- **질량–스프링 시스템**: 사면체의 모든 모서리가 XPBD 거리 구속(스프링). k = 6·E·V/L²이면 등방 중심력 스프링망의 영률이 정확히 E가 돼요(λ = μ = E/2.5). 표면 모서리에는 피막 스프링이 따로 있어요.
- **사면체 부피 구속**: 스프링망이 못 채우는 체적 탄성률을 더해서 푸아송 비를 맞추고, 사면체가 뒤집히는 것도 막아요. 호흡과 볼 부풀리기는 사면체의 정지 부피를 바꾸는 방식이라 몸이 실제로 부풀어요.
- **점탄성 (맥스웰 가지)**: 각 스프링의 점성 정지 길이가 현재 길이를 향해 τ로 크리프해요. 오래 누르면 더 깊어지고, 놓으면 일부는 바로, 나머지는 천천히 돌아와요. 빠른 터치는 단단하게, 느린 터치는 말랑하게 느껴지는 것도 이 때문이에요.
- **켈빈–포크트 감쇠**: 모서리마다 속도 단계에서 암시적으로 푸는 대시팟. 상대 속도만 줄이니 에너지를 늘릴 수 없어서 β가 아무리 커도 안정적이고, 강체 운동은 감쇠하지 않으며, 짧은 모서리(고주파 떨림)를 가장 세게 잡아요.
- **형상 정합 (Shape Matching)**: 질량 중심과 최적 회전(극분해, Müller 2016 반복법)으로 맞춘 원래 모양으로 전체를 끌어당기는 전역 형상 기억. 몸의 좌표계도 여기서 나와요.
- **라플라시안 표면 변형**: 표면 입자의 우산 연산자 δ = xᵢ − 평균(이웃)의 법선 성분(이산 평균 곡률)을 정지 값으로 유지하는 굽힘 구속. 현재 법선 기준이라 회전에 무관해서 기울어진 귀와 싸우지 않아요.
- **공간 해싱**: 표면 입자 자기 충돌(누르기·흔들기 중에만), 메시 생성의 블루노이즈 샘플링, 렌더 정점의 최근접 입자 탐색에 써요.
- **GPU 정점 변위**: CPU는 입자 하나당 텍셀 4개(아핀 맵 [F | c]와 눌림 정보)만 올려요. 렌더 정점(7천–2만 2천 개)은 가장 가까운 입자 8개의 아핀 맵을 매끈한 가중치로 섞어 위치를 구하고, 법선은 변형 기울기에서 바로 계산해요(n ∝ F·t₁ × F·t₂). CPU가 메시를 갱신하거나 법선을 다시 계산하지 않아요.
- **PBD 충돌**: 접시와의 접촉(정지/운동 마찰), 손끝 패치, 변형률·부피 하드 한계는 위치 투영으로 처리해요.

### 손가락

- 터치는 먼저 시뮬레이션 표면에 광선을 쏘고, 그 주변 렌더 삼각형을 CPU에서 똑같이 스키닝해 다시 쏴서 **변형된 피부 위의 정확한 점**을 찾아요.
- 손끝은 **힘으로 제어**돼요. 누르는 힘이 손끝 깊이를 밀고, 가중치가 매끈하게 떨어지는 입자 패치가 재질의 반력으로 그 깊이를 밀어내요. 그래서 같은 힘이라도 말랑할수록 더 깊이 들어가요.
- 손가락을 움직이면 패치가 화면 평면에서 따라가요. 접선 힘이 쿨롱 마찰(μ·누르는 힘 + 점착력)을 넘으면 손끝이 미끄러지며 그 자리에서 다시 잡아요(스틱–슬립). 바깥으로 당기는 힘이 그립을 넘으면 빠져요.
- 귀처럼 얇은 부분은 다섯 방향으로 두께를 재서 알아내고, 누르는 대신 꼬집어 잡아요.
- 빠른 톡과 느린 꾹은 손끝 힘의 상승 곡선과 점탄성 때문에 다르게 반응해요.
- 손끝 자국은 정점 셰이더에서 손끝 구를 정확히 감싸도록 한 번 더 다듬어요.

### 보이는 것

- 눌린 곳은 살짝 어두워지고(차폐), 압축된 곳은 색이 짙어지고, 늘어난 곳은 얇아져서 옅어져요.
- 피부가 한 방향으로 압축되면 그 방향을 가로지르는 미세한 주름이 생겨요(표면 계량 텐서의 최소 주신장).
- 얇은 귀와 눌린 곳으로 빛이 비쳐 보이는 실리콘 반투명, 시선 반사, 실시간 그림자(자기 그림자 포함).
- 얼굴은 텍스처가 아니라 셰이더가 정지 좌표 기준으로 그려서, 몸이 늘어나면 표정도 같이 늘어나요.

### 성능

- 물리는 웹 워커에서 자체 60 Hz 시계로 돌고, 메인 스레드는 마지막 두 상태를 보간해서 화면 주사율로 그려요(물리와 렌더링 분리). 렌더링이 느려도 물리는 실시간을 유지해요.
- 품질 자동 선택: 기기 코어 수·메모리·포인터 종류·GPU 이름으로 낮음/보통/높음을 고르고, 시뮬레이션 해상도·서브스텝·렌더 메시·그림자 해상도가 함께 바뀌어요.
- 물리 프레임이 예산(11 ms)을 넘으면 서브스텝을 줄이고(재질 느낌이 변하지 않는 하한까지), 여유가 생기면 되돌려요. 렌더가 느리면 픽셀 비율과 그림자 필터를 낮춰요.
- 자기 충돌은 누르거나 흔드는 동안에만, 하드 한계 검사는 두 서브스텝에 한 번씩 돌아요.
- 워커를 못 쓰는 환경에서는 같은 코드가 메인 스레드에서 돌아요.

## 테스트

```bash
# 헤드리스 물리 테스트: 8가지 상황 + 점프 + 오래 누르기를
# 질감 3종 × 품질 3종 × 극단값 설정에서 모두 확인
node squishy/tests/physics.test.mjs           # 전체 (수십 분)
node squishy/tests/physics.test.mjs --quick   # 기본 질감, 보통 품질

# 브라우저 테스트: 실제 페이지에서 마우스·멀티터치로 8가지 상황을 재현하고
# 스크린샷과 안정성 리포트를 남김 (playwright 필요)
cd squishy && python3 -m http.server 8000 &
node tests/browser-scenarios.mjs out
```

확인 항목: NaN, 뒤집힌 사면체(메시 붕괴), 뒤집힌 피부 면(찢어짐), 폭주 속도, 과도한 변형률·부피 손실, 놓은 뒤 진동 감쇠, 손대지 않은 쌍둥이 시뮬레이션과 비교한 형태 복원.

8가지 상황: ① 중앙 세게 누르기 ② 볼 누르기 ③ 귀 잡아당기기 ④ 양쪽 동시에 누르기 ⑤ 한 손가락 누른 채 다른 손가락 끌기 ⑥ 빠르게 연속 주무르기 ⑦ 흔들고 놓기 ⑧ 여러 부위 연속 변형.

## 실행

ES 모듈과 모듈 워커를 쓰기 때문에 `file://`로 바로 열면 동작하지 않아요. 이 폴더에서 아무 정적 서버나 띄우면 돼요.

```bash
cd squishy
python3 -m http.server 8000
```

그다음 `http://localhost:8000`을 열어요. three.js는 jsDelivr CDN(`three@0.170.0`)에서 불러와서 인터넷 연결이 필요해요. WebGL 2가 필요해요.

## 배포 (GitHub Pages)

저장소 **Settings → Pages**에서 브랜치와 `/ (root)` 폴더를 지정하면 `https://<사용자명>.github.io/<저장소명>/squishy/` 주소로 열려요.

│       └── client.js   메인 스레드 쪽: 워커/대체 실행, 상태 보간
└── tests/
    ├── physics.test.mjs     헤드리스 물리 테스트 실행기
    ├── scenarios.mjs        8가지 상황과 판정 기준
    ├── harness.mjs          가상 손가락 리그와 측정
